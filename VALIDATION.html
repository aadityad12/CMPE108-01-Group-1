Validation

These are software checks, not results of a writer-personalization study.

  • Loaded the official pinned checkpoint with all 673 model-state entries; 6,389,041 model parameters.
  • Ran CPU bidirectional beam-search inference on the official example; the output is recorded in the guide.
  • Ran two actual optimization updates and decoding for full-model, decoder-only, and FFN-LoRA adaptation on a small integration fixture.
  • Passed six unit/integration tests: tokenization/metrics; image polarity; nested splits; LoRA identity/gradients; decoder freezing; adapter save/reload/resume.
  • Generated writer-summary CSV files and a learning-curve plot from integration fixtures. Fixture performance is not presented as scientific evidence.
  • Compiled the Python files and syntax-checked both Slurm shell scripts.
  • Started the local Gradio 6.30.0 app, recognized an uploaded image, uploaded ten labeled test fixtures, trained a one-step LoRA adapter through the app, downloaded its checkpoint, and recognized again using the session's personalized model.
  • Checked guide HTML structure, links within the guide, archive file inclusion, and absence of third-party weights/datasets.

Executed core checks with Python 3.12, PyTorch 2.5.1+cpu, NumPy 1.26.4, Pillow 11.0.0, einops 0.8.0, and OpenCV 4.10.0. The recommended Python 3.10 environment is a compatible installation target, but was not separately executed here.

Not performed here: GPU/CUDA execution, SJSU login or Slurm submission, container build, full CROHME-2023/HME100K import, writer-provenance verification, public-data access approval, or the final research experiments. Dataset-specific directory paths and metadata must be checked after download. Browser rendering of the guide was unavailable; HTML structure and link targets were checked.
